# Portable setup profile format

[Main README](README.md) · [Setup profile guide](docs/setup-profiles.md) · [Manual authoring](docs/manual-profile-workflow-authoring.md) · [Shared assets](docs/shared-assets.md)

The primary portable setup extension is `.comfyuisetup`. Legacy `.comfysetup`, YAML, and JSON profiles remain readable for migration.

## Purpose

A profile describes how to reconstruct a working ComfyUI setup. It is not a ZIP backup of the checkout, custom nodes, virtual environment, models, outputs, or credentials.

An exact profile records:

- the ComfyUI repository and fetchable base revision;
- a compact overlay containing only allowed core files changed, added, or deleted relative to that base;
- the source Python runtime, platform, architecture, accelerator, and PyTorch runtime/index;
- every installed Python distribution and exact version in `environment-lock.yaml`;
- original dependency manifests from ComfyUI and installed custom nodes;
- public custom nodes as Registry/Manager IDs and/or validated Git repositories in `custom_nodes.yml`;
- sanitized source only for a plugin that remains unresolved after all Registry, Manager, configured-catalog, metadata, and Git lookups;
- model/workflow manifests, source catalogs, shared-library policy, prerequisites, and validation steps.

## Archive layout

```text
profile.yaml
environment-lock.yaml
custom_nodes.yml
dependency-manifests.yml
dependency_manifests/
  comfyui/
  custom_nodes/<node-id>/
comfyui_overlay/          # changed/new core files only
models.yaml
workflows.yaml
asset-sources.yaml
libraries.yaml
metadata.yaml
README.txt
embedded_plugins/         # unresolved plugins only
```

New profiles do not contain `.venv`, installed site-packages, public custom-node source trees, complete ComfyUI checkouts, models, machine-specific paths, or local wheels. Legacy bundles that already contain `embedded_wheels/` remain readable and checksum-verified.

## `profile.yaml`

Schema 4 example:

```yaml
schema_version: 4
kind: comfyui-setup-profile
id: example-setup
name: Example Setup [cp312-cuda124-torch2_6_0_cu124]
display_name: Example Setup [cp312-cuda124-torch2_6_0_cu124]
version: 2026.7.17
publisher: Example Author
compatibility:
  profile_version: 2026.7.17
  pep440: true
  exact: true
  python_version: 3.12.9
  python_abi: cp312
  accelerator: nvidia
  backend_version: '12.4'
  accelerator_abi: cuda124
  pytorch_version: 2.6.0+cu124
  pytorch_abi: torch2_6_0_cu124
  abi_tag: cp312-cuda124-torch2_6_0_cu124
comfyui:
  repository: https://github.com/Comfy-Org/ComfyUI.git
  branch: master
  preferred_commit: 0123456789abcdef0123456789abcdef01234567
  exact: true
  source:
    type: remote
    repository: https://github.com/Comfy-Org/ComfyUI.git
    ref: 0123456789abcdef0123456789abcdef01234567
    overlay:
      payload: comfyui_overlay
      base_commit: 0123456789abcdef0123456789abcdef01234567
      changed_files: [main.py]
      deleted_files: []
python:
  preferred: "3.12.9"
  fallbacks: ["3.12.9"]
torch:
  version: "2.6.0"
  source_accelerator: nvidia
  source_backend_version: "12.4"
  exact_backend_index: https://download.pytorch.org/whl/cu124
  exact_backend: true
constraints:
  numpy: 2.4.4
# environment_lock is stored only in environment-lock.yaml.
# Custom nodes are stored only in custom_nodes.yml.
# Dependency-manifest inventory is stored only in dependency-manifests.yml.
```

`version` and `compatibility.profile_version` must normalize to the same PEP 440 version. `abi_tag` contains tag-safe characters and combines the Python ABI, accelerator runtime, and full PyTorch build identity. Compatibility metadata is optional when reading legacy profiles; new exports always write it. See [PEP 440 versions and ABI compatibility tags](docs/abi-compatibility-tags.md).

## Core repository overlay

The exporter never snapshots the complete ComfyUI directory. It determines the configured origin (or the official ComfyUI repository when no custom repository is declared), finds a fetchable base commit, and computes a Git name-status diff. The archive carries only allowed changed/new files and a deletion list.

The overlay always excludes:

- `custom_nodes/` and content installed or generated by nodes;
- `.venv`, embedded Python, site-packages, and build caches;
- models, inputs, outputs, temp, user data, logs, and databases;
- generated launchers and manager-owned shared-path files;
- symlinks, credentials, secrets, and unsafe/oversized payloads.

Installation clones/checks out the base first, verifies the overlay checksum, applies changed files, and then applies deletions. When no reliable base exists, the profile records the repository/branch and warns that unidentified core edits cannot be preserved; it does not silently turn into a full backup.

## `environment-lock.yaml`

The lock records every installed distribution discovered through Python metadata, including transitive and manually installed packages. It records final working versions rather than trying to solve the environment from node requirements alone.

```yaml
environment_lock:
  schema_version: 1
  mode: exact
  complete: true
  source:
    python: 3.13.5
    implementation: CPython
    os: linux
    architecture: x86_64
    accelerator: nvidia
    torch_version: 2.12.1+cu130
    torch_cuda: "13.0"
  packages:
    - name: click
      version: 8.1.8
      requirement: click==8.1.8
      install: true
      portable: true
      source: index
    - name: example-node-package
      version: 1.0.0
      requirement: example-node-package==1.0.0
      install: false
      portable: true
      source: source-tree
      managed_by: comfyui-or-custom-node-source
      source_path: custom_nodes/example-node
      editable: true
    - name: flash-attn
      version: 2.8.3.post1
      requirement: flash-attn==2.8.3.post1
      install: false
      portable: true
      source: managed
      managed_by: accelerated-package
  nonportable_packages: []
  explicitly_omitted_packages: []
```

New-export package source types are:

- `index`: exact version resolved from an approved public/configured package index;
- `github`: immutable public Git reference with a resolved commit;
- `managed`: installed by the PyTorch or acceleration lifecycle, still constrained and audited;
- `source-tree`: supplied by the reconstructed ComfyUI or custom-node source and reinstalled from `source_path`;
- `unsupported-direct-url` or `ambiguous-installed-distributions`: not safely reproducible and therefore marks the lock incomplete.

`embedded-wheel` is accepted only for backward compatibility with older profiles. New exports do not create wheel payloads. A package originally installed from a local wheel is recorded by exact name/version and is resolved through package indexes, configured wheel catalogs, a public source/build rule, or the accelerated-package lifecycle.

Core and Manager requirements are reconciled under the final lock. After the complete exact environment lock is installed, custom-node manifests are reconciled and retained as audit evidence but are not submitted for a second installation. Manager-only acquisition uses `--no-deps`; repository-backed nodes are cloned directly. Acceleration and repair operations remain constrained and are followed by the exact package audit. Exact dynamic acceleration entries carry the source distribution identity (`package_name`) and the installer also recovers that identity from `environment-lock.yaml` for older same-version profiles; target CUDA detection cannot silently swap one CuPy, TensorRT, or ONNX Runtime distribution family for another. Before a captured `requirements.txt` is passed to uv, each ordinary package requirement is compared with the verified version in the exported working environment. If the manifest excludes that verified version, the generated installation copy is rewritten to the verified exact version and an explicit override record is emitted. This prevents invalid pairs such as `comfy-kitchen==0.2.21` in a repository manifest together with `comfy-kitchen==0.2.20` in the exact lock. Direct URLs and package-index options are not silently rewritten. After node installation, the lock is reapplied, dependency metadata is audited, ComfyUI performs a quick startup validation, and the complete package/version set is checked again.

## Dependency manifests and conflict resolution

The archive copies `requirements*.txt`, `pyproject.toml`, `python.toml`, `uv.lock`, `manager_requirements.txt`, and `setup.cfg` when present in ComfyUI or a custom node. `dependency-manifests.yml` identifies each file and checksum. These files preserve intent and provenance; the verified environment lock remains authoritative for the final reproducible version set.

The exporter parses declared Python requirements, evaluates applicable environment markers, compares them across ComfyUI and every selected node, and records:

- each declaration and owning manifest;
- the exact version already proven to work in the source environment;
- incompatible declaration ranges;
- unparsed lines requiring review.

The working environment lock is authoritative when declarations overlap or conflict. Manifests are included for audit and installation planning; they are not a reason to archive node source.

## Custom-node resolution and `custom_nodes.yml`

At first startup on each UTC day, ComfyUI Setup Manager refreshes:

1. the official Comfy Registry paginated node catalog at `https://api.comfy.org/nodes`;
2. the maintained ComfyUI-Manager `node_db` channels `dev`, `new`, `legacy`, `forked`, and `tutorial`;
3. both `custom-node-list.json` and `extension-node-map.json` for each legacy channel.

The last usable cache is retained through partial network outages. **Rescan nodes** can force an immediate refresh.

Resolution uses, in order, local node/Git/package metadata, local Manager caches and snapshots, user mappings and configured catalogs/channels, the daily Registry and legacy Manager cache, direct Registry search, and validated repository hints. Ambiguous matches are not guessed.

A resolved node is a compact descriptor:

```yaml
- id: comfyui-kjnodes
  name: ComfyUI-KJNodes
  folder: comfyui-kjnodes
  source:
    type: remote
    manager_id: kjnodes
    manager_version: 1.2.3
    repository: https://github.com/kijai/ComfyUI-KJNodes
    preferred: manager
    resolved_by: comfy-registry-daily
    resolution_trust: Official
```

Installation clones the validated repository first whenever one is available. A Manager/Registry ID is used only when no repository can be resolved, and acquisition is performed without dependency installation. Node `requirements.txt` files are reconciled for audit; complete exact profiles do not install them twice. `install.py` is classified as `none`, `dependencies-only`, or `required`: dependency-only scripts are skipped under a complete exact lock, while genuine bootstrap/lifecycle scripts still run.

Only a node that remains unidentified after every lookup uses:

```yaml
source:
  type: embedded
  payload: embedded_plugins/private-local-plugin
  layout: directory
```

That fallback payload is sanitized, checksum-protected, and limited to source files. Public or Manager-installed nodes are never embedded merely because the installed folder lacks `.git`, uses a normalized folder name, is dirty, or has no locally recoverable commit.

Duplicate destination identities require an explicit keep/omit choice with complete paths displayed. The choice is recorded without writing machine-specific paths into the profile.

Exact export refuses only when required metadata is ambiguous or unsafe: no Python inventory, duplicate distributions with the same canonical name, an unresolved plugin when fallback embedding is disabled, an unsafe unresolved payload, or a duplicate-node choice that has not been made.

## `models.yaml`

```yaml
models:
  - id: example-checkpoint
    name: Example checkpoint
    source_id: publisher
    url: https://example.org/example.safetensors
    destination: checkpoints
    filename: example.safetensors
    required: false
    selected: true
```

`required: true` means installation cannot be considered complete when the asset fails. Suggested items remain optional.

## `workflows.yaml`

```yaml
workflows:
  - id: example-workflow
    name: Example workflow
    source_id: github
    url: https://example.org/example.json
    destination: examples
    filename: example.json
    required: false
```

## `asset-sources.yaml`

```yaml
asset_sources:
  models:
    schema_version: 1
    sources: []
    entries: []
  workflows:
    schema_version: 1
    sources: []
    entries: []
```

The installer merges included public source metadata into the user's YAML catalogs before it resolves selected assets. Local file paths, credentials, request headers, and tokens are not exported.

## `libraries.yaml`

```yaml
libraries:
  shared_models:
    enabled: true
    required: false
    description: Use one external model library.
  shared_workflows:
    enabled: true
    required: false
    description: Use one external workflow library.
  paths_embedded: false
```

Portable archives describe the policy. The receiving computer chooses its own paths.

## Legacy profiles

Profiles created before the full environment lock remain readable. Their explicit constraints and dependency-repair rules are honored, but they cannot retroactively recover every package version, ABI identity, or local artifact that the old exporter discarded. Re-export the original working installation with the corrected 0.8.7 exporter to obtain a complete environment lock, ABI tag, compact public-node descriptors, and payloads only for unresolved local plugins.

## Security rules

- archive paths may not be absolute or contain `..`;
- repository sources must satisfy repository policy;
- package indexes must satisfy package-source policy;
- direct package Git references must use public GitHub HTTPS and a resolved commit;
- legacy embedded wheels, when importing an older profile, must be `.whl` files beneath `embedded_wheels/` and pass SHA-256 verification; new exports do not create wheel payloads;
- embedded plugin payloads exclude models, environments, caches, secrets, user data, and outputs;
- all YAML is validated before installation.
